Overview

In this homework we implemented a path tracer. For Part 1, we generated rays from the camera and implemented intersection tests for triangles and spheres. In Part 2 we built a BVH to make ray intersection faster, since checking every triangle becomes really slow for bigger scenes. We then implemented direct lighting in Part 3 and indirect lighting in Part 4, where we trace additional bounces to get global illumination. Finally, Part 5 implements adaptive sampling, so we don't need to use the same number of samples for every pixel. From the results, the BVH made a big difference for large meshes (around 6,800× for Lucy), and adding more bounces and samples helped us render the lighting more realistically.

Part 1: Ray Generation and Scene Intersection

Ray generation and the rendering pipeline

To render each pixel, we take several samples at random positions inside the pixel and average their colors. First, for each sample we add a random offset in \([0,1)^2\) to the pixel's bottom left corner. We then divide by the width and height of the image to convert it into coordinates in \([0,1]^2\). These coordinates are passed into the camera to generate a ray. We trace the ray and get its radiance, and after doing this for all samples we average them to get the final pixel color.

For ray generation, we first use camera space, with the camera at the origin looking in the \(-z\) direction. The sensor plane is at \(z=-1\). From the horizontal and vertical field of view we calculate the half width and height of the sensor:

\[ w = \tan\left(\frac{hFov}{2}\right), \qquad h = \tan\left(\frac{vFov}{2}\right). \]

Since \((0,0)\) represents the bottom left of the sensor and \((1,1)\) the top right, the position corresponding to our sample is:

\[ \mathbf{p}_{cam} = \big( (2x - 1)\, w,\; (2y - 1)\, h,\; -1 \big). \]

Because the camera is at the origin, we can use this position as the direction of the ray in camera space. We transform it into world space using the camera to world matrix and normalize the direction. The ray starts at the camera position. We also set its minimum and maximum \(t\) using the near and far clipping distances, so intersections outside of that range are ignored.

Primitive intersection

For each primitive, we implemented two intersection functions. One function only returns whether the ray intersects the primitive, which we use for shadow rays. The other function also stores the intersection information such as \(t\), the normal and the material. We check that the intersection is between the minimum and maximum \(t\) of the ray. When we find a valid hit, we update the maximum \(t\) to the new value. Thus, later intersections only count if they are closer than the previous one, so we end up with the closest intersection.

Triangles. For triangles, we used the Moller Trumbore algorithm. We can represent a point on a triangle using barycentric coordinates, similar to what we did in HW1. By setting this equal to the ray equation, we solve for the distance \(t\) and two barycentric weights using dot and cross products. If the ray is parallel to the triangle, we reject it. Otherwise we check whether all three weights are nonnegative and whether \(t\) is inside the ray's range. We also use the barycentric weights to interpolate the three vertex normals and get the normal at the intersection point.

Spheres. For the sphere intersection, we used the sphere equation with center \(\mathbf{o}\) and radius \(R\). By substituting the ray into \(\lVert \mathbf{p}-\mathbf{o}\rVert^2-R^2=0\), we get a quadratic equation \(at^2+bt+c=0\), where \(a=D\cdot D\), \(b=2(O-\mathbf{o})\cdot D\) and \(c=\lVert O-\mathbf{o}\rVert^2-R^2\). If the discriminant is negative, there is no intersection. Otherwise we first check the smaller root \(t_1\), and if it is before the minimum \(t\), we check the larger root \(t_2\). This also handles the case where the ray starts inside the sphere. We still check that the chosen root is in range. For the normal, we take the normalized vector from the sphere center to the hit point.

Part 2: Bounding Volume Hierarchy

BVH construction

For the BVH, we used a recursive construction. First we get the range of primitives for the current node and calculate a bounding box that contains all of them. If the number of primitives is small enough, we make it a leaf node and stop splitting. Otherwise we need to divide the primitives into two groups.

To divide them, we calculate a bounding box of the primitive centroids, which are their center positions. We choose the longest axis of this box and use its midpoint as the split position. Primitives whose centroids are on one side go to the left child, and the remaining ones go to the right child. We rearrange the primitives so the two groups are together, then recursively build the two child nodes.

One edge case we handled is when all the centroids are at the same position. In that case the midpoint split puts all primitives into one group, so the recursion would not make progress. Hence, in that case we divide the range into two halves by the number of primitives instead.

Splitting heuristic. We chose the longest axis of the centroid bounding box because this is where the primitives are spread out the most. Splitting across this direction can reduce overlap between the two child boxes, so it is easier to skip one of them when tracing a ray. We used the centroid box instead of the whole primitive bounding box because one large triangle could make that box much bigger, even when most of the other triangles are close together.

We also chose this method because it is simple and does not require sorting. We only go through the primitives to find the split, and the BVH for Lucy's 133,796 triangles took about 0.04 seconds to build. Other methods such as a median split or surface area heuristic might make a better tree, but our method worked well enough for the scenes we tested.

BVH traversal

Bounding box test. We used the slab method to check whether a ray intersects a bounding box. For each of the x, y and z axes, we calculate the two \(t\) values where the ray crosses the box planes, using \(t=(\text{plane}-O_a)/D_a\). We precompute \(1/D_a\), and swap the two values if the ray is traveling in the negative direction. We then take the latest entry time and earliest exit time over all three axes, while also checking the valid ray interval. If the entry is after the exit, the ray misses the box.

Traversal. Starting from the root, we first test if the ray intersects the node's bounding box. If it does not, we can skip everything in that node. If the node is a leaf, we check the primitives stored inside it. Otherwise we recursively check both children, since an intersection could be in either child. Whenever we find a closer primitive, we update the ray's maximum \(t\), just like in Part 1. Thus, we can skip boxes that are farther away than the closest hit found so far. For shadow rays, we return once we find any intersection, since we only need to know whether something blocks the light.

Part 3: Direct Illumination

Direct lighting

For direct lighting, we first implemented the diffuse BSDF, which just returns the reflectance divided by \(\pi\) since a diffuse surface reflects light equally in all directions. For zero bounce lighting we return the emission of the surface the camera ray hits, so the only thing that shows up is the area light. Then we implemented two ways to estimate the direct light at a hit point. Both of them estimate the reflection equation with Monte Carlo:

\[ L_{out} \approx \frac{1}{N} \sum_{j=1}^{N} \frac{f(w_j \to w_o)\, L_{in}(w_j)\, \cos\theta_j}{p(w_j)} \]

Uniform hemisphere sampling. For this method, we pick random directions uniformly in the hemisphere around the normal, so every direction has the same pdf of \(1/(2\pi)\). The number of samples is the number of lights times the samples per area light. For each direction we shoot a ray from the hit point, starting slightly off the surface so it does not hit itself. If the ray hits something, we take that object's emission, which is zero unless it is a light. Then we multiply by the BSDF and \(\cos\theta\), divide by the pdf, and average over all the samples.

Light sampling. For this method, we sample the lights directly instead. We go through every light in the scene. For a point light we only take one sample, since every sample would be the same, and for an area light we take the samples per area light. Each sample gives us the direction to the light, the distance to it, the pdf and the incoming radiance. If the light is behind the surface, we skip it. Otherwise we shoot a shadow ray toward the light that stops just before reaching it. If nothing blocks the shadow ray, we add the BSDF times the radiance times \(\cos\theta\), divided by the pdf. We average the samples for each light and then add up all the lights. Thus, this method also works for point lights, which random hemisphere directions would basically never hit.

Part 4: Global Illumination

Indirect lighting

For indirect lighting, we need to choose a new direction after a ray hits a diffuse surface. We used cosine weighted hemisphere sampling, so directions closer to the surface normal are more likely to be selected. The PDF for the sampled direction is \(\cos\theta/\pi\), and the BSDF for a diffuse surface is the reflectance divided by \(\pi\).

We implemented indirect lighting recursively. First, the camera ray starts with the maximum ray depth, and we decrease this depth by one for every bounce. At an intersection, we calculate direct lighting using what we implemented in Part 3. If there is still depth left, we sample a new direction from the BSDF, start a new ray slightly away from the surface, and trace that ray again. The returned radiance is then weighted by the BSDF, cosine term and sampling probabilities:

\[ L_{out} \mathrel{+}= \frac{f(w_i \to w_o)\, L_{in}\, \cos\theta_i}{p(w_i)\, p_{cont}}. \]

We used Russian roulette so rays do not keep bouncing forever. After a bounce, we continue with probability \(p_{cont}=0.65\). If the path stops, we do not add any more indirect light from that path. If it continues, we divide the contribution by 0.65 to account for the paths that stopped. We always allow the first indirect bounce when the maximum depth is greater than 1.

For the final camera ray color, we add the emission of the surface that the camera ray hits (zero bounce light) and the lighting returned by the recursive function. We also implemented the option to display only the \(m\)th bounce. For that case, we only add the direct lighting at the selected bounce, and for \(m=0\) we only show emission.

Part 5: Adaptive Sampling

Implementation

For Part 5, we implemented adaptive sampling instead of taking the maximum samples for every pixel. The idea is that some pixels converge earlier, so we can stop sampling them and spend more time on noisier pixels. In our implementation, we store the sum of sample brightness values \(x_k\) and also the sum of their squares, \(s_1=\sum x_k\) and \(s_2=\sum x_k^2\). After each batch, we calculate the mean, variance and confidence interval:

\[ \mu = \frac{s_1}{n}, \qquad \sigma^2 = \frac{1}{n - 1}\left(s_2 - \frac{s_1^2}{n}\right), \qquad I = 1.96 \cdot \frac{\sigma}{\sqrt{n}}. \]

Here \(I\) is half the width of the 95% confidence interval. We check if \(I\) is smaller than the tolerance multiplied by the mean \(\mu\). If so, we consider the pixel converged and stop taking more samples. Otherwise we continue until the maximum sample count. The final pixel color is still calculated by averaging the samples actually taken, and we record that number for the sample rate image. We also clamp the variance to zero if floating point error makes it slightly negative, so taking the square root does not cause an issue.

Results

We tested adaptive sampling on the bunny and spheres at 480×360. We set a maximum of 2048 samples per pixel, batch size 64, tolerance 0.05, 1 light ray and max ray depth 5. In the sample rate images, red areas are pixels that needed almost all 2048 samples, while blue areas converged with fewer samples.

From the results, the light and the bright walls stopped sampling much earlier than the darker parts. The ceiling, the shadows below the objects and the sides of the bunny and spheres away from the light used more samples. These areas receive more indirect lighting, so the samples vary more. Also, our stopping condition uses the tolerance relative to the mean \(\mu\). Thus, darker pixels need a smaller confidence interval before stopping.
